黑板课讲稿：什么是 Agent 的 Skill（技能文件）

形式：你站在黑板/白板前，一边写板书一边讲。
结构：每一节 = 【黑板板书】（你写在板上的字，精炼）+ 【讲解词】（你嘴上说的，口语化）。
对象：小白 / 有点基础但没写过 skill 的人。
全程一条主线：是什么 → 它在哪 → 长什么样 → 怎么改 → 怎么判断好坏 → 举个例子。

开场（30 秒，先不写板书，先说）

【讲解词】

之前几期我都是对着镜头念稿子。今天换个方式——我站到黑板前面，像老师讲课那样，把一个东西一条一条列出来给你讲清楚。

今天要讲的东西叫 Skill，技能文件。

你可能听过"给 AI 装技能""让 Agent 学会一个活儿"——具体是怎么装的？装进去的到底是个啥？很多人以为是什么复杂的插件、要写代码。

不是。我先把结论写在黑板正中间：

【黑板板书】（大字，居中）


Skill = 一份写给 AI 看的「操作手册」
        （就是一个 .md 文本文件）

【讲解词】

就这么简单。它不是代码，不是程序，就是一个纯文本文件，里面用人话写着"遇到这类活儿，该怎么一步步干"。今天我把这份手册是什么、放在哪、长什么样、怎么写怎么改、怎么判断写得好不好，全给你讲透，最后带你看一个真实的例子。

第一节：是什么（先解释，后命名）

【讲解词】

先别管"Skill"这个词，我先给你讲个场景。

假设你请了一个非常聪明的新员工。脑子好、学东西快，但他第一天上班，什么都不知道——不知道你们公司报销走哪个流程、代码提交前要先跑哪个检查、给客户发邮件用什么模板。

聪明没用，因为他没有"你们这儿的规矩"。

那你会怎么办？你会写一张便签 / 一份 SOP贴在他桌上："报销：先填 A 表，找李姐签字，再上传系统。" 下次他一遇到报销，照着做就行，不用再问你。

Skill 就是这张便签。只不过——它是贴给 AI 看的。

【黑板板书】


是什么？
┌─────────────────────────────────┐
│ 聪明的新员工 = 大模型（很强，但不懂你的规矩）│
│ 一张 SOP 便签   = Skill（告诉它你的规矩）    │
└─────────────────────────────────┘

一句话：Skill 把「一类活儿的正确干法」
        写成文字，喂给 AI，让它照着做。

【讲解词】

注意我说的是"一类活儿"，不是"一件事"。

"帮我改这句话"——这是一件事，说完就完了。

"以后凡是写小红书文案，都要先起钩子、控制在 300 字、结尾带 3 个话题"——这是一类活儿的规矩，这种才值得写成 Skill。

所以记住这个判断标准，等下还要用：

【黑板板书】（角落，框起来，标记"★记住"）


★ 值得写成 Skill 的，是【会反复遇到的一类任务】，
  不是【一次性的一件事】。

第二节：它在哪（在 AI 知识体系里的位置）

【讲解词】

现在你知道 Skill 是什么了。第二个问题：它在整个 AI Agent 的"脑子"里，处在什么位置？

我把一个 Agent 拥有的"知识"分成三层，从下往上画：

【黑板板书】（画三层楼，从下往上写）


        ┌────────────────────────────┐
第 3 层  │  Skill 技能   → 会干这类活儿的「手册」│  ← 今天讲这层
        │              （反复用、要照着步骤做）  │
        ├────────────────────────────┤
第 2 层  │  Memory 记忆  → 记住关于你的「事实」   │
        │              （你是谁、你的偏好、环境）  │
        ├────────────────────────────┤
第 1 层  │  大模型本身   → 通用的「聪明」        │
        │              （语言、常识、推理）       │
        └────────────────────────────┘

【讲解词】

从下往上讲：

第一层，大模型本身。 这是地基，是那个"聪明的新员工"。它有通用的语言能力、常识、会推理。但它对你一无所知，对你的具体干法一无所知。

第二层，记忆（Memory）。 这层解决"它记不记得你"。比如它记住"这个用户是清华的、说话喜欢直接、讨厌啰嗦"。记忆存的是事实、是关于你的信息——是名词。

第三层，就是今天的 Skill。 这层解决"它会不会干某类活儿"。Skill 存的是流程、是怎么做——是动词。

一句话区分这两层，你一定要分清，很多人搞混：

【黑板板书】（重点框）


★ Memory 记忆 = 记住「是什么 / 谁」（事实、名词）
★ Skill 技能  = 知道「怎么做」    （流程、动词）

【讲解词】

举个对比就懂了：

  • "用户叫张一文，是清华美院的" —— 这是记忆。
  • "写简历时，要真实事实拔高措辞、补可信量化、绝不编造获奖" —— 这是技能。

    • 看出来了吗？前者是一条信息，后者是一套做事的规矩。位置不一样，作用不一样。

    所以 Skill 在体系里的位置是：站在大模型的通用能力之上，把它从"通用的聪明"变成"在你这件具体的事上很专业"。

    第三节：长什么样（文件结构）

    【讲解词】

    好，最实操的部分来了。一个 Skill 文件，打开它，里面到底长什么样？

    我先把它拆成两大块，这是整个结构的骨架，一定先记住：

    【黑板板书】（一个文件的示意图，上下两块）

    
一个 Skill 文件（SKILL.md）
╔══════════════════════════════╗
║  ① 头部（帽子 / frontmatter）      ║  ← 给机器看的「标签」
║     name:  这个技能叫什么          ║
║     description: 什么时候该用它 ★  ║
╠══════════════════════════════╣
║  ② 正文（身体 / 用人话写的手册）    ║  ← 给 AI 读的「怎么做」
║     · 这是什么、什么时候用          ║
║     · 一步步怎么做（带具体命令/例子）║
║     · 有哪些坑、怎么判断做对了       ║
╚══════════════════════════════╝

    【讲解词】

    上面这块叫"头部"，专业点叫 frontmatter。它是给"系统"看的标签，最关键的就两行：

  • name：这个技能叫什么名字。
  • description：什么情况下应该用这个技能。 这一行我打了个星，因为它是整个文件最重要的一行——等会儿讲"怎么判断好坏"还要回来说它。

    • 下面这块叫"正文"，就是用大白话写的操作手册。它一般包含这么几段，我列出来：

    【黑板板书】（正文的标准段落，编号列出）

    
正文的标准骨架：
  1. Overview 概述   —— 这技能是干嘛的、为什么需要
  2. When to Use     —— 什么时候用、什么时候【别】用
  3. 步骤 / 怎么做    —— 一步步，带具体命令和例子
  4. Pitfalls 坑     —— 常见错误 + 怎么避开
  5. 检查清单        —— 怎么确认这活儿干对了

    【讲解词】

    你看这五段，其实就是一个老师傅带徒弟的完整逻辑：先说"这是干嘛的"（1、2），再说"跟着我这么做"（3），再说"新手最容易在这儿摔跤"（4），最后说"你怎么知道自己做对了"（5）。

    不是每一段都必须有，但至少要有：概述 + 什么时候用 + 具体怎么做 + 坑。缺了这几样，它就不像一份合格的手册。

    第四节：怎么写、怎么改（改的方法）

    【讲解词】

    现在讲你最关心的：我要动它，怎么动？ 分两种情况。

    情况一：从零写一个新的

    【黑板板书】

    
写一个新 Skill 的三步：
  第 1 步：先想清楚「触发条件」
          —— 一句话说清「什么时候用它」
  第 2 步：把你自己干这活的步骤，一条条写下来
          —— 你平时怎么做，就怎么写，别抽象
  第 3 步：把踩过的坑补上（这步最值钱）

    【讲解词】

    重点是第 3 步。新手写的手册，只写"正确步骤"；老师傅写的手册，会写"这里有个坑，别踩"。 后者才是真正省事的。你自己踩过的坑，写进去，就是这个 Skill 最值钱的部分。

    情况二：改一个已有的（更常见）

    【讲解词】

    更多时候你不是从零写，而是在用的过程中发现它不对、不够，去改它。改也分两种改法，这是重点：

    【黑板板书】（重点，两种改法对比）

    
怎么改？两种方式：

  A. 小改（改错字、加一条坑、把触发条件说得更准）
     → 局部替换：找到那句话，换掉它。别动别的。

  B. 大改（整个流程都要重写）
     → 整篇重写。

★ 原则：能小改，就别大改。
       每次只动该动的地方，别顺手改别的。

    【讲解词】

    为什么强调"能小改别大改"？因为大改容易把原来对的东西一起弄坏。你本来只是想加一句提醒，结果整篇重写，一不小心把某个关键步骤删了、把某个例子改错了——这就是给自己埋雷。

    所以改 Skill 的心法就一句话：外科手术式地改，精准，只碰该碰的地方。

    还有一个特别高频的改动，单独拎出来说：改那句 description（什么时候用它）。

    【黑板板书】

    
最常改、也最该改好的一句：description
  ✗ 差：「写文案」
  ✓ 好：「当用户要写小红书文案、说"帮我发小红书"、
         "写个种草笔记"时，用这个技能」

    【讲解词】

    为什么这句这么重要？因为 AI 是靠这句话来决定"要不要用这个技能"的。你这句写得含糊，比如就写俩字"写文案"，那 AI 根本不知道啥时候该掏出这个技能来用——写得再好也白搭，因为它想不起来用。

    所以这句要写成"什么场景、用户说了什么话，就该用它"。写触发条件，别写功能名。

    第五节：怎么判断好不好（质量标准）

    【讲解词】

    最后一个大问题：我写完/改完了，怎么知道它是好是坏？ 我给你四条标准，你拿这四条去卡，一卡一个准。

    【黑板板书】（四条判断标准，编号大字）

    
判断一个 Skill 好不好，看四条：

  ① 触发准不准？
     —— 该用的时候能想起来用，不该用时不乱用
        （全看 description 那句写得准不准）

  ② 步骤能不能照着做？
     —— 是「具体命令/例子」，还是「正确的废话」？
        「先做好准备工作」= 废话
        「先运行 xxx 命令确认环境」= 能照做

  ③ 有没有写坑？
     —— 只有正确步骤 = 新手手册
        写了「这里容易错」= 老师傅手册

  ④ 长度合不合适？
     —— 太短：没干货   太长：抓不住重点
        （经验值：几千字，一屏能看到主干）

    【讲解词】

    挨个说：

    第一条，触发准不准。 前面反复强调的那句 description。这是第一道关，过不了这关，后面都白搭。

    第二条，步骤能不能照着做。 这条最能区分好坏。你看一段步骤，问自己一句话："一个新手拿着这句，能直接动手吗？" 如果写的是"要注意做好前期准备"——这是正确的废话，等于没说。如果写的是"先跑这个命令，看到 xxx 就说明对了"——这才叫能照着做。具体到能执行，才算数。

    第三条，有没有写坑。 刚才讲过，不重复。有坑的是好手册。

    第四条，长度。 太短，说明没实货，几句话糊弄；太长，说明没提炼，AI 和人都抓不住重点。经验上，一个好的 Skill 大概几千字，主干一屏能看个大概。太长了，就该把细节拆出去。

    【黑板板书】（总结成一句口诀，框起来）

    
★ 一句话验收口诀：
  「该用能想起、上手能照做、踩坑有提醒、长短刚刚好」

    第六节：举个真实例子（落地）

    【讲解词】

    光讲抽象的没用，我给你看一个真实的 Skill 文件的头部，就是我实际在用的，一个叫"系统化调试"的技能。你看它是不是就长成我们黑板上画的那样。

    【黑板板书】（照抄真实头部，讲解每一行）

    
真实例子：一个「调试」技能的头部
─────────────────────────────
name: systematic-debugging          ← ① 它叫什么
description: "4-phase root cause     ← ② 什么时候用：
   debugging: understand bugs           任何技术问题——测试失败、
   before fixing."                       线上 bug、性能问题…
─────────────────────────────
正文第一句（Overview）：
  "乱改一通浪费时间还制造新 bug。
   核心原则：动手修之前，永远先找到根本原因。"

    【讲解词】

    你看，完全对得上我们讲的结构：

  • name —— 它叫什么。
  • description —— 写的是什么时候用："任何技术问题——测试失败、线上 bug、性能问题"。你看它没写"这是个调试工具"（那是功能名），它写的是触发场景。这就是第五节第①条的正面示范。
  • 正文一上来就是 Overview，一句话点出"为什么需要它"：乱改浪费时间。然后甩出核心原则。

    • 这就是一个合格 Skill 的样子——帽子说清"啥时候用"，身体说清"怎么做、别踩啥坑"。

    收尾（30 秒）

    【黑板板书】（把整节课的六个问题连成一条线，擦掉细节只留主干）

    
今天这条线，你带走：

Skill = 写给 AI 的操作手册（一个 .md 文本）
  │
  ├─ 在哪：站在大模型之上，管「怎么做」（≠记忆管「是什么」）
  ├─ 长啥样：头部（叫什么+啥时候用）+ 正文（怎么做+坑+检查）
  ├─ 怎么改：能小改别大改，外科手术式，尤其改好 description
  └─ 好不好：该用能想起 · 上手能照做 · 踩坑有提醒 · 长短刚好

    【讲解词】

    好，今天这堂黑板课就到这。你记住一句话就够了：

    Skill 不是什么高深的代码，它就是一份"你把自己会干的一类活儿，用人话写下来交给 AI"的操作手册。 你会写便签，你就会写 Skill。

    下次咱们就真的动手，从零写一个出来。下课。

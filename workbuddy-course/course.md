# 模块一 · 入门筑基

## 第 1 课 · 认识 WorkBuddy：智能体 ≠ 聊天机器人

### 🎯 本课目标
用一句话说清 WorkBuddy 是什么，以及它和 ChatGPT / 文心一言的**本质区别**——这决定了你以后该怎么"喂"它。

### 📖 知识点：从"顾问"到"助理"
**WorkBuddy 是腾讯出的 AI 办公智能体（Agent）。** 关键词是"智能体"——它不只回答，它会**动手干活**：读你的文件、拆解步骤、上网查资料、写文档、跑数据、做 PPT，最后交给你一个**能直接用的成品**。

打个比方：
- 普通 AI 聊天 = 一个**顾问**：你问它，它给建议，活还得你自己干。
- WorkBuddy = 一个**助理**：你交代任务，它自己拆步骤、找资料、动手做，做完把成品递到你手上。

**三个最直观的区别：**

| 对比 | 普通 AI 对话 | WorkBuddy |
|------|------|------|
| 它能干嘛 | 只能回答、给建议 | 真的帮你执行任务 |
| 文件操作 | 你得自己复制粘贴 | 直接读写你授权的文件 |
| 交付物 | 一段文字 | 可下载的 Word/PPT/表格/网页/视频 |
| 工作方式 | 一问一答 | 拆任务→找资料→执行→产出→可验收 |

### 💡 一个思维转变（本课最重要）
以后你交给它的是**"任务"**，不是**"问题"**。
- 问题思维：「PPT 怎么做好看？」→ 它给你一堆建议。
- 任务思维：「按这个大纲做一份 15 页商务风 PPT，配色深蓝。」→ 它直接给你 .pptx。

这个转变贯穿全课。你越把它当"能干活的同事"，它越有用。

### ✋ 动手感受
先不用装软件。打开官网 **www.workbuddy.cn**，看首页演示，体会"一句话出成品"。心里种下一句话：**我交给它的是任务，不是问题。**

### 📝 课后作业
列出 3 件你上班最烦、最重复的活（整理表格、写日报、改文件名……）。后面几节我们挨个用 WorkBuddy 干掉它们。

## 第 2 课 · 下载 · 安装 · 登录 · 积分体系

### 🎯 本课目标
5 分钟装好并登录，**看懂积分是怎么花的**——这是新手最容易懵、也最容易浪费钱的地方。

### ✋ 三步装好
**第 1 步 · 下载**：官网 www.workbuddy.cn 点「下载」，选你的系统（Windows / Mac），双击安装包一路「下一步」。
**第 2 步 · 登录**：首次打开用**微信扫码登录**，手机上验证即进入。
**第 3 步 · 领新手积分**：新用户赠送 **2500 积分**（基础体验包，有效期约 30 天）。

### 📖 知识点：积分是"油费"，要有感觉
积分就是任务的"油费"。不同任务耗油差很多——**建立"贵/便宜"的直觉，是省钱第一步**：

| 任务类型 | 大致消耗 | 直觉 |
|------|:---:|------|
| 纯文字任务（写文档、周报、总结） | 很少 | 随便用 |
| 数据分析、做 PPT、调研报告 | 中等 | 正常用 |
| 生成图片 | 约 5–10 积分/张 | 悠着点 |
| 生成视频 | 约 50–100 积分/段 | 先看余额 |

> ⚠️ 数字随官方活动会变，以软件内为准。**规律不变**：文字便宜、多模态贵。养成"生成图/视频前瞄一眼余额"的习惯。

**关于付费（新手先用免费额度）**：标准版约 99 元/月起、高级版约 199 元/月起、旗舰版约 999 元/月起。2500 积分足够你跑完本课程大部分练习。

### 🔧 进阶（小白可跳过）：接入自己的模型
如果你有自己的 API（如公司给的 OpenAI 兼容接口），可在设置里接入。**注意：目前只支持 OpenAI 兼容协议的 API。** 新手阶段完全不用管，用它自带的即可。

## 第 3 课 · 主界面 · 任务 · 工作区三层结构

### 🎯 本课目标
打开软件不发懵——认清界面结构，特别是理解 WorkBuddy 独有的"**工作区**"概念（这是它能当团队用的基础）。

### 📖 知识点一：界面三大区域
打开后从左到右分成三块：

**① 侧边栏（左）——任务清单**：做过的任务按文件夹列在这，可搜索、按状态筛选。底部是头像和「设置」（连接器、技能都在设置里开）。
**② 对话区（中）——干活的地方**：核心区。顶部任务标题，中间对话记录，底部输入框——**可直接把文件拖进去上传**。
**③ 结果区（右）——拿成品的地方**：这是它和聊天机器人的分水岭！4 个标签：
- **产物**：看生成的文档/PPT　- **全部文件**：列出所有产出　- **变更**：显示文件被改了哪　- **预览**：实时预览网页/PPT

### 📖 知识点二：任务 vs 工作区（关键）
- **任务**：一次对话解决一件事，产物存在这个任务里。
- **工作区（Workspace）**：一个**装着多个文件和多轮任务的项目空间**。你把素材放进工作区，多个任务（甚至多个 Agent）共享同一批文件。

> 💡 为什么重要？后面搭"专家团"时，多个 Agent 要读写**同一份产品事实**——工作区就是它们的共享桌面。现在只要记住：**简单活开任务，复杂项目开工作区。**

### ✋ 动手操作
1. 发一句：「帮我写一段 100 字的公司午餐会通知」
2. 观察：中间出现回复，右侧「产物」出现成品，点开能下载
3. 新建一个工作区，把一份文件拖进去，感受"项目空间"

### 📝 课后作业
用自己的话讲清"任务"和"工作区"的区别。熟练"拖文件到输入框"这个动作。

## 第 4 课 · 三种工作模式：Craft / Plan / Ask

### 🎯 本课目标
搞懂三种模式，什么活切哪种——这是用好它、且不白花积分的**核心开关**。

### 📖 知识点

| 模式 | 一句话理解 | 什么时候用 |
|------|------|------|
| **Craft（你说我做）** | 立即行动，直接开干 | 日常任务首选：写文档、做 PPT、分析数据 |
| **Plan（先想后做）** | 先给方案，你点确认它再动手 | 复杂项目：建网站、大改动、方向没定时 |
| **Ask（只聊不动手）** | 只回答，不碰你的文件 | 只想咨询、对比方案、问问题时 |

**新手记住一句话：90% 的日常活用 Craft 就够了。**
- 简单活（写通知、做表）→ **Craft**，立刻做。
- 复杂活（搭网站、整理大项目）→ **Plan**，让它先出计划，你确认再执行，避免跑偏。
- 只想问问、不想它动我文件 → **Ask**，安全地聊。

### ✋ 动手对比
同一需求两种模式各试一次：
- **Craft**：「做一份 5 页读书分享 PPT，主题《原子习惯》」→ 直接开做
- **Plan**：发同样的话 → 它先列计划（几页、每页讲啥）等你确认

你会立刻明白：**越复杂的活，越值得先 Plan。**

### 💡 避坑（省钱第一原则）
新手最常见错误：一上来对着超复杂需求用 Craft，结果方向全错还白花积分。**复杂任务先 Plan。**

### 📝 课后作业
把第 1 课记下的 3 件烦人活，各判断该用 Craft 还是 Plan，写下理由。

## 第 5 课 · 完成第一个真正的任务（任务简报 + 验收）

### 🎯 本课目标
跑通一个完整闭环：**下任务 → 拿成品 → 验收**。学会写"任务简报"和"验收标准"，这是所有高阶用法的地基。

### 📖 知识点：一个好任务的三件套
不要只丢一句需求。一个能一次做对的任务，包含三件事：

1. **任务简报**：背景 + 目标 + 具体要求 + 输出格式（第 24 课细讲万能公式）。
2. **交付格式**：你要 Word 还是 Markdown？几页？什么风格？说清楚。
3. **验收标准**：你凭什么说"这活干好了"？先想清楚，再让它做。

> 💡 蓝皮书 L1 能力的毕业标准是：**同一类任务，连续 3 次输出都能直接验收通过。** 达到了，就可以把它升级成模板（L2）。

### ✋ 实操：写一份"周会通知"并验收
**任务简报（Craft 模式发）：**
```
背景：我是市场部，本周五下午 3 点开周会，地点大会议室。
目标：写一份周会通知。
要求：语气正式、包含时间地点、需带上的材料（各自本周数据）、
      迟到规则一句话。
格式：正文 300 字以内 + 一句话标题。
```
**验收清单（你自己对照）：**
- [ ] 时间、地点、材料齐全？
- [ ] 语气符合你公司文化？
- [ ] 字数、标题符合要求？

不满意就直接追问："标题再正式一点""加一句线上参会链接占位"。它会在原稿上改。

### 💡 小技巧：先框架后细节
复杂产物别一次求完美。**先让它出框架 → 你确认结构 → 再生成完整版 → 最后微调**，比一次丢一大堆要求效果好得多。

### 📝 课后作业
挑第 1 课的一件活，按"简报 + 格式 + 验收标准"三件套写一遍，跑通一次完整闭环。记录你改了几轮才验收通过。

## 第 6 课 · 四种能力形态：普通任务 / Skill / 专家 / 专家团

### 🎯 本课目标
建立**全局认知地图**——WorkBuddy 有四种"用法档位"，用对档位事半功倍，用错就是杀鸡用牛刀或小马拉大车。

### 📖 知识点：四档能力，对应四类问题

| 用法 | 本质 | 适合的问题 | 例子 |
|------|------|------|------|
| **普通任务** | 通用理解与执行 | 一次性的清楚任务 | 写个通知、做张表 |
| **Skill（技能）** | 特定工具能力 | 需要稳定执行某个动作 | 下抖音视频、发公众号、生成 PDF |
| **专家** | 人设 + 方法论 + 工具链 | 明确领域的单点专业问题 | 数据分析专家、小红书运营专家 |
| **专家团** | 多位专家 + 协作流程 | 需拆解、并行、汇总的复杂项目 | 视频生产团队、投资私董会 |

**关键区别（划重点）：**
- **普通 Agent 分析销售数据**：读数据 → 出图 → 总结趋势。
- **数据分析"专家"**：先理解业务目标 → 定核心指标 → 查数据质量 → 找异常 → 分析原因 → 给可执行建议。
  → 同样一份数据，专家因为带着**方法论**，产出深度完全不同。

一句话记忆：
> 普通 WorkBuddy = 通用 AI 同事；**专家 = 有岗位和专业经验的 AI 同事**；**专家团 = 一整支能自己分工的 AI 团队**。

### 💡 怎么选档位
- 活很清楚、一次性 → **普通任务**
- 要反复做同一个动作 → 找/装一个 **Skill**
- 要专业深度（研报、运营、法务）→ 召唤/创建一位 **专家**
- 要跨多个专业、多步骤、能并行的大项目 → 召唤一个 **专家团**

后面模块三讲 Skill，模块五讲专家与专家团。现在你只需要有这张地图。

### 📝 课后作业
把你工作中的 5 件事，各归到四档中的一档，并写一句"为什么是这档"。这张归类表就是你的个人使用地图。

# 模块二 · 办公实战

## 第 7 课 · 办公三件套：一句话出 Word / Excel / PPT

> 😩 **你是不是也这样？** 周报写到晚上九点、明天要汇报 PPT 还是白板、领导甩来一句"做个表"——办公三件套是打工人最大的时间黑洞。这一课就是来把它们从"一小时"压到"一句话"的。

### 🎯 本课目标
用一句话生成周报（Word）、表格（Excel）、演示文稿（PPT），并从右侧结果区下载。这是职场人用得最多的功能。

### 📖 知识点：说清需求，结果差十倍
诀窍是**把需求说清楚**（万能公式：背景 + 目标 + 具体要求 + 输出格式，第 24 课细讲）。

❌ 差：「帮我写个周报」（它不知道你干了啥，只能瞎编）
✅ 好：「我是运营，本周做了 3 场直播、5 篇推文、参加选题会。生成本周周报，Word，分『本周完成』『下周计划』『问题与风险』三部分，语气正式。」

### ✋ 实操案例

**案例 A · 周报（Word）**
```
我是市场部专员，本周完成：新品发布会筹备、2 篇公众号推文、
对接 3 家媒体。写一份本周工作周报，Word，
分「本周完成」「下周计划」「需要支持」三板块，语气正式。
```

**案例 B · 项目排期表（Excel）**
```
做一份项目排期表，Excel，含列：任务名称、负责人、
开始时间、结束时间、状态。预填 10 行示例数据。
```

**案例 C · 从大纲生成 PPT**
```
按以下大纲做 15 页 PPT，简洁商务风，配色深蓝+白：
1. 封面：产品名+Logo  2. 目录
3-5. 行业痛点（3页）  6-9. 核心功能（4页，每页一个）
10-12. 竞品对比（3页）  13. 商业模式  14. 团队  15. 联系方式
```
它自动排版、配图、统一风格，右侧产出可下载的 **.pptx**。

### 💡 小技巧：分步迭代
做 PPT 建议：**先出框架 → 确认结构 → 生成完整 PPT → 微调风格**。比一次丢一大堆要求好得多。追问示例："第 3 页配一张图""整体字号调大""把竞品对比改成表格"。

### 📝 课后作业
用案例 A 模板，换成你真实的工作，生成一份自己的周报并下载。

## 第 8 课 · 数据分析与可视化：拖一份 Excel 出报告

> 😰 **最怕这句话：「你帮我分析下这个数据」。** 你连 VLOOKUP 都记不全，透视表点开就晕，可领导下午就要结论。这一课教你：把 Excel 一拖，让它替你找异常、给原因、出图表——你负责拿结论去汇报。

### 🎯 本课目标
把一份 Excel 丢给它，自动清洗、算汇总、出图表，产出带交互图表的分析报告——**不用会函数、不用会画图**。

### 📖 知识点：全自动五步
你只要把文件拖进对话框，用大白话说想看什么，它全自动完成：**读取 → 清洗 → 计算 → 画图 → 生成报告**。

### ✋ 实操案例：销售数据分析
1. 把 Excel（假设有：日期、产品、区域、销售额）拖进对话框
2. 输入：
```
分析这份销售数据，按月汇总各产品线销售额，
生成柱状图和趋势折线图，找出销售额 Top 5 区域，
输出一份含图表的分析报告（HTML 格式）。
```
3. 不到 1 分钟，右侧出现可预览的 **HTML 报告**，含交互式图表。

**还能让它做的分析：**
- 「找出这份数据里的异常值和下降最快的产品」
- 「按季度对比，用一段话总结趋势」
- 「把结论做成 3 页 PPT，给领导汇报用」

### 💡 小技巧
- 看不懂的列先用 **Ask 模式**问：「这份数据有哪些字段？每列什么意思？」
- 报告不满意直接追："图表换暖色系""加一段执行摘要""按区域再拆一层"，它在原报告上改。
- **数据脏也没关系**：让它先"清洗并说明清洗了什么"，你就知道它动了哪些数据。

### 🚧 边界与人工关口
数据分析结论**可信度依赖数据质量**。涉及给领导/客户的关键结论，务必人工复核口径（比如"销售额"是否含退款、时间窗口对不对）。**AI 缩短处理时间，判断仍归你。**

### 📝 课后作业
找一份真实数据（销售、考勤、账单都行），出一份分析报告，体验"不会 Excel 也能做数据分析"。

## 第 9 课 · 文件识别与批量处理：发票 / 图片 / 文档

### 🎯 本课目标
让它批量重命名、归类、识别文件——那些手动做要半天的机械杂活。以"发票整理登记"为进阶案例。

### 📖 知识点
WorkBuddy 能**读写你授权的本地文件夹**。重复 100 遍的机械操作，一句话交给它。
> ⚠️ 安全提示：它只能操作你**授权**的文件夹。第一次操作某目录时看清提示、确认路径再放行。

### ✋ 实操案例

**案例 A · 批量重命名图片**
```
读取 D:\Photos\2026 下所有图片，按拍摄日期重命名为
20260601_153000.jpg，再按月份归类到子文件夹（2026-06/）。
```
它读每张图的 EXIF，批量改名+分类，给你一份处理日志。

**案例 B · 整理下载文件夹**
```
整理下载文件夹，按类型分到子文件夹：
文档→Docs、图片→Images、安装包→Installers、压缩包→Archives。
```

**案例 C · 发票整理与登记（进阶，L2）**
```
读取「报销发票」文件夹里所有发票图片/PDF，识别每张的：
发票号码、开票日期、金额、税额、销售方名称，
汇总成 Excel 台账，统计总金额，标出金额异常（如超 5000）的行。
```
这一步考验**文件识别 + 表格 + 金额复核**三件事。识别完成后，**金额务必人工抽查几张**——这是财务场景的铁律。

### 💡 小技巧
- 拿不准会不会误删？先用 **Plan 模式**让它列"打算怎么操作"，确认后再执行。
- 重要文件先备份，养成习惯。

### 📝 课后作业
挑电脑里最乱的文件夹（下载夹通常是重灾区），让它整理归类一次。有条件的用真实发票试案例 C。

## 第 10 课 · 会议协同：录音 → 纪要 → 待办 → 周报

> 😩 **开一小时会，整理纪要又要一小时。** 谁说的什么、谁负责跟进、下次几点开——全靠你边听边记还怕漏。这一课把录音一传，纪要、待办、跟进自动出，散会 5 分钟就能发群里。

### 🎯 本课目标
把"开会"变成一条流水线：**会议录音 → 结构化纪要 → 待办清单 → 汇报材料**，会议结束不再是终点。

### 📖 知识点：会议的价值在会后
大多数人开完会就散了，行动项没人跟。WorkBuddy 能把会议纪要变成"能追踪的待办"。链路：
> 录音/转写 → 纪要（决议 + 讨论 + 遗留问题）→ 待办（谁、做什么、何时）→ 同步到文档/IM → 生成周报

### ✋ 实操案例

**案例 A · 从录音/文字稿出纪要**
```
这是今天产品评审会的录音转写（附件）。整理成会议纪要：
1. 一句话会议结论  2. 关键决议（编号）
3. 讨论要点  4. 遗留问题
5. 待办清单：任务 | 负责人 | 截止时间（表格）
```

**案例 B · 待办转跟进**（配合腾讯文档连接器，见第 12 课）
```
把上面的待办清单写入我腾讯文档「本周待办」，
并在每个负责人名字后加一句一句话的跟进话术草稿。
```

**案例 C · 多次会议汇总成周报**
```
读取我这周三次会议的纪要，提炼成一份汇报周报：
本周关键决策、进展、卡点、下周重点，给领导看，正式简洁。
```

### 🚧 边界
纪要里**不要把"讨论中的推测"写成"已确认的结论"**。让它区分"决议"和"待确认项"，重要决议人工核对原话。

### 📝 课后作业
下次开会录一段音（或用文字稿），跑一遍 A→B，体验"会议结束 5 分钟出纪要和跟进"。

## 第 11 课 · 深度调研：从一个问题到一份带证据的报告

### 🎯 本课目标
让它联网调研一个课题，产出一份**带来源证据、可追溯**的专业报告——而不是一堆看起来对但没出处的"AI 口水"。

### 📖 知识点：调研的关键是"证据可追溯"
好的调研报告 ≠ 长。核心是**每个关键结论都能溯源**。让它输出时带上：
> 结论 → 支撑证据 → 原始来源链接 → 可信度/待确认项

用 **Plan 模式**做调研最稳：它先列调研提纲、信息源计划，你确认方向再让它开搜，避免跑偏浪费积分。

### ✋ 实操案例：市场/竞品调研
```
用 Plan 模式：调研 2026 年国内 AI 编程助手市场。
先列调研提纲和信息源计划让我确认，然后：
1. 主要玩家对比（产品、定价、差异化）——做成表格
2. 技术趋势  3. 市场规模与增长
4. 每个关键数据附来源链接，无法核实的标「待确认」
输出 3000 字 Markdown 报告 + 一张竞品对比表 + 一张来源证据表。
```

**进阶 · 多源交叉验证**：涉及重要数字，让它"用多个来源交叉验证，冲突的地方标注出来"。这就是蓝皮书说的"来源补证与事实核查"。

### 💡 小技巧
- 报告太长抓不住重点？追一句："开头加一段 200 字执行摘要，给忙的人看。"
- 想要不同深度？"基础版给资料摘要，进阶版给证据矩阵。"

### 🚧 边界（重要）
AI 适合**缩短资料处理时间，不适合隐藏来源直接给结论**。投资、法律、医疗类调研，观点和最终判断必须由人承担。让它做"资料 + 证据 + 待确认项"，把"拍板"留给你。

### 📝 课后作业
选一个你工作相关的课题，用 Plan 模式做一份带来源证据表的调研报告。检查：有几个结论是能点开链接溯源的？

# 模块三 · 连接器与技能生态

## 第 12 课 · 连接器：打通邮箱 / 文档 / 微信 / Notion

### 🎯 本课目标
学会开启"连接器"，让 WorkBuddy 直接操作你的邮箱、腾讯文档、飞书、微信、Notion、GitHub 等外部服务——不用来回切软件。

| 连接器 | 一句话能干嘛 |

| 金山文档 | 「在『客户案例』文件夹批量创建 50 个文档，命名客户001~050」 |
| 飞书 | 「读飞书『需求文档』下所有文档标题，整理成目录」 |
| Notion | 「搜 Notion 里含『重装系统』的页面，按最近编辑排序」 |
| GitHub | 「列出仓库 my-project 最近 10 个未关闭 Issue，按优先级排」 |
| Canva 可画 | 「做一张公众号封面，900×383，主题『AI 效率工具』，简约清新」 |
| 腾讯问卷 | 「创建满意度问卷，5 道单选+2 道简答，主题产品体验」 |
| ima 知识库 | 「从 ima 搜『产品方法论』的笔记」 |

### ✋ 实操案例：跨平台一条龙
开启 ima + 腾讯文档两个连接器后：
```
1. 从我的 ima 知识库搜关于「产品方法论」的笔记
2. 整理成结构化文档
3. 保存到腾讯文档，命名「产品方法论整理」
```
一句话跨三个平台完成 检索 → 整理 → 创建。

### 💡 微信集成（提醒神器）
设置 → Claw 设置 → 微信助手集成，扫码后 WorkBuddy 的消息能同步到你微信。适合做提醒："提醒我下午 3 点取快递"。
> ⚠️ 注意：电脑需一直开机；你在电脑发的消息不会同步回微信。

### 🚧 边界
连接器有**写入权限**（能建文档、发邮件）。涉及"外发"（发邮件给客户、写入 CRM）的操作，**默认让它先出草稿，你确认再发**——别让它自动外发未经确认的内容。

### 📝 课后作业
开启 QQ 邮箱连接器，汇总今天未读邮件。体验"不打开邮箱也能收邮件"。

## 第 13 课 · 技能 Skill：给它装外挂（安装 + 实战）

### 🎯 本课目标
搞懂"技能 Skill"是什么，安装官方技能，解锁下视频、发公众号、生成 PDF 等专项能力。

### 📖 知识点：Skill vs 连接器
- **连接器**：连"你已有的账号平台"（你的邮箱、你的文档）。
- **技能 Skill**：装"某种专门能力"（比如"会下抖音视频"这个本领）。

**官方技能举例（在设置/技能市场安装）：**

| 技能 | 能干嘛 | 提示词示例 |
|------|------|------|
| 抖音批量下载 | 下载某账号全部视频 | 「下载抖音账号 XXX 主页全部视频到本地」 |
| Wechat Publisher | 一键发文到公众号草稿箱 | 「把 my-article.md 发到公众号草稿箱，封面用第一张图」 |
| PDF 文档生成 | 从文本生成精美 PDF | 「把以下内容生成商务风 PDF，含封面/目录/页码」 |
| 公众号爆款查询 | 搜全网 10w+ 找灵感 | 「搜『AI 工具』相关 10w+ 爆款，列标题+公众号+时间」 |
| 浏览器自动化 | 网页截图/填表/抓数据 | 「抓豆瓣电影 Top250 名称/评分/导演，整理成表格」 |
| 公众号文案创作 | 生成长文，指定风格 | 「以『AI 办公效率翻倍』为题写 2000 字，口语化」 |
| stock-advisor | 股票技术+基本面分析 | 「分析这只票的 K 线和财报，给综合评级」 |

> 附录 B 有更完整的技能清单（含资讯类、事实核查类）。

### ✋ 实操案例：内容创作一条龙
装好「公众号文案创作」+「Canva」+「Wechat Publisher」后：
```
1. 以「5 个提效 AI 工具」为主题写一篇 1500 字公众号文，轻松口语风
2. 用 Canva 配一张封面图，主题同上，简约清新
3. 把文章发到我的公众号草稿箱，用刚才的封面
```

### 💡 进阶了解
高手会把一堆技能放中央文件夹，用"目录软链接"批量挂给 WorkBuddy。你现在只要知道：**技能可以不断加，加得越多它越全能。** 需要什么本事，去技能市场找找。

### 🚧 边界
下载类技能（抖音、视频）**要遵守平台条款、版权和合理使用**。目的是学习结构、做参考，不是搬运。

### 📝 课后作业
逛一遍技能市场，找 1 个和你工作最相关的技能，安装并试用一次。

## 第 14 课 · 打造自己的 Skill：把书和视频蒸馏成能力

### 🎯 本课目标
从"用现成技能"升级到"造自己的技能"——把一本书、一个教程视频、一套你的方法论，蒸馏成 WorkBuddy 可反复执行的 Skill。这是 L3 的分水岭。

### 📖 知识点：为什么要自造 Skill
现成技能解决通用动作。但你的**独门方法论**（比如你写周报的固定框架、你审合同的检查清单、你做竞品分析的评分表）没人替你封装。把它变成 Skill，就等于**把"你怎么做这件事"固化下来，以后一句话触发，每次都按你的标准来**。

**一个 Skill 通常包含三样东西：**
1. **触发场景**：什么时候用它（"当我要写竞品分析报告时"）。
2. **方法论/步骤**：按什么框架、什么顺序做（你的 SOP）。
3. **输出模板**：产物长什么样（固定的表格、章节、字段）。

### ✋ 实操思路：把一份"方法论"蒸馏成 Skill
**第一步 · 喂原料**（把书/视频稿/你的 SOP 拖进工作区）：
```
这是我做竞品分析的方法论文档（附件）。请你把它蒸馏成一个
可复用的工作流：1. 什么情况触发  2. 分几步、每步做什么
3. 最终输出的固定模板（章节+表格字段）。先给我看这个蒸馏结果。
```
**第二步 · 固化成技能**：确认蒸馏结果后，按 WorkBuddy 技能市场/设置里的"创建技能"流程，把这套框架保存成你的专属 Skill（也可创建为"专家"，见第 19 课）。
**第三步 · 测试**：新开一个任务触发它，喂一个真实竞品，看是否严格按你的模板产出。连续 3 次达标 = 这个 Skill 可用了。

### 💡 小技巧
- **从窄开始**：先造一个只做一件事的小技能（如"生成标准周报"），跑顺了再扩。
- **模板越具体越稳**：把输出模板的字段、章节写死，产出一致性会大幅提升。

### 📝 课后作业
挑一件你每周都做、且有固定套路的活，把套路写成"触发+步骤+模板"，蒸馏成一个 Skill，测试 3 次。

## 第 15 课 · 知识系统：ima / Obsidian / 收藏再利用

### 🎯 本课目标
解决一个普遍痛点：**收藏 = 存了就忘**。让 WorkBuddy 把你散落在各处的笔记、收藏、文档变成"能再次用起来"的知识系统。

### 📖 知识点：收藏不是知识管理
"能再次用起来才是。" WorkBuddy 能连接 ima 知识库、Obsidian、WPS、腾讯/飞书文档，把碎片信息**检索出来 → 结构化 → 关联 → 再产出**。

一个个人知识工作流通常是：
> 移动端随手捕捉（ima/微信）→ 定期归集 → 打标签分类 → 需要时检索 → 组装成新产物（报告/文章/方案）→ 来源"体检"（哪些信息过期了）

### ✋ 实操案例

**案例 A · 把散落笔记变成一篇文章**
```
从我的 Obsidian 里搜所有含「Agent 设计」的笔记，
去重后按主题聚类，帮我组织成一篇 2000 字文章的提纲，
标出每个观点来自哪条笔记（可溯源）。
```

**案例 B · 知识库体检**
```
检查我 ima 知识库里「AI 工具」标签下的笔记，
标出哪些信息可能已过期（涉及具体版本号、价格、榜单的），
列出需要更新的清单。
```

**案例 C · 移动捕捉 + 定期整理**
配合微信助手：随手把想法发给 WorkBuddy，设一个每周日的自动任务（见第 16 课），"把本周捕捉的碎片笔记归集分类，存入 Obsidian"。

### 💡 小技巧
让它在整理时**始终保留来源**（哪条结论来自哪个文件），这样你的知识系统才可信、可追溯，而不是又一堆"AI 生成的看起来对的话"。

### 📝 课后作业
选一个你的笔记库（ima/Obsidian/文档都行），让它做一次"知识库体检"，看看有多少收藏其实早就该更新了。

# 模块四 · 自动化与可靠性

## 第 16 课 · 定时自动化任务：让它自己干活

> 🚀 **想象一下：** 每天早上打开电脑，昨天的邮件汇总、今天的待办、行业热点已经躺在你微信里了——你一个字没敲。这一课教你设"定时自动任务"，让重复的活它自己干，你只管看结果。

### 🎯 本课目标
设置一个"定时自动执行"的任务，比如每天早上自动汇总邮件、发日报，全程无需动手。

### 📖 知识点
WorkBuddy 能创建**定时/周期任务**——设好时间规则，到点自动跑。适合日报、周报、定时提醒、定期巡检这类"每天都要做一遍"的事。
> ⚠️ 关键限制：自动任务执行时，**你的电脑必须开着机**（它在你本机跑）。

### ✋ 实操案例

**案例 A · 每日邮件晨报**
```
创建一个自动化任务：
- 每天早上 9:00 执行
- 获取邮箱过去 24 小时的邮件
- 按重要程度分类汇总（发件人、主题、摘要）
- 通过微信助手把汇总发给我
```
（需先开邮箱连接器 + 微信助手集成）

**案例 B · 每周自动周报草稿**
```
每周五 17:00 自动执行：
读取我这周在腾讯文档「工作日志」的记录，
生成周报草稿，保存到腾讯文档「周报」文件夹。
```

**案例 C · 定时提醒**
```
每个工作日下午 6 点提醒我：填今天的工时表。
```

### 💡 小技巧：先手动，再自动
- **先手动跑一次**，确认结果满意，再设成自动化——避免定时跑出一堆错的。
- 自动任务可靠性依赖：电脑开机 + 连接器保持授权 + 网络正常。重要任务多留意几天。

### 📝 课后作业
设置一个属于你的每日自动任务（晨报、提醒、日报都行），观察它第二天有没有准时执行。

## 第 17 课 · 资讯整合流水线：信息流变每日通知

### 🎯 本课目标
搭一个"不吵"的 AI 日报系统：把 GitHub 热点、AI 行业动态、论文、公众号、新闻热榜等多个信息源，变成**可筛选、可解释、可追踪**的每日通知。

### 📖 知识点：资讯整合最怕两件事
一是信息太多，重要的被淹没；二是通知太吵，最后大家当背景噪音。好的资讯系统要**先筛选再推送**。

**统一工作流（所有资讯通知都是这条链）：**
> 订阅源与检索 → 抓取与去重 → 分类与重要性评分 → 摘要/翻译/影响判断 → 来源补证与事实核查 → 生成通知卡片 → 推送到飞书/微信/邮件/文档 → 归档与复盘

| 环节 | 解决什么 | 输出 |
|------|------|------|
| 收集 | 从新闻/热榜/GitHub/arXiv/RSS/公众号拉候选 | 候选列表、链接、时间、来源 |
| 去重 | 同一事件被多源重复报道 | 合并同源，保留首发/权威 |
| 筛选 | 不是所有新内容都值得推 | 重要性评分、相关性、风险等级 |
| 摘要 | 长文/论文/README 太长 | 三句话摘要、影响判断、适用人群 |
| 核查 | 避免把传闻/营销稿当事实 | 证据表、可信度、待确认项 |
| 通知 | 固定格式推给对应人群 | 飞书卡片、微信消息、日报文档 |

### 🧩 可用的资讯类 Skill
| Skill | 通知什么 |
|------|------|
| 腾讯新闻 | 热点、早晚报、领域新闻（管理层早报） |
| AIHOT | AI 模型/产品/行业/论文动态（AI 行业日报、技术雷达） |
| GitHub 热门项目 | 今日/本周/本月热门，可按语言过滤（研发日推） |
| GitHub AI 趋势追踪 | AI 热门项目趋势周报 |
| ArXiv 论文追踪 | 最新论文搜索与总结 |
| 博客监控 | 竞品博客、官方 changelog、技术博客 |
| wechat-article-search | 监控行业 KOL、竞品公众号、爆款选题 |
| 多引擎搜索 / Tavily / Exa / 元宝搜索 | 给重要信息做二次验证、来源补证 |
| jiaozhen-factcheck / 辟谣助手 | 争议信息加可信度判断 |

### ✋ 实操案例

**案例 A · GitHub 每日热点通知**
```
创建自动任务：每天早上 7 点抓 GitHub Trending 和 AI 热门项目，
按语言/主题/star 增长过滤，只推 Top 5-10 个，
每个给一句「是否值得试用」判断，发到我微信。
```

**案例 B · AI 行业日报（需先装 AIHOT skill）**
先装技能：`帮我安装这个 skill：https://aihot.virxact.com/aihot-skill/`
```
每天固定时间从 AIHOT 拉 AI 动态，按模型/产品/行业/论文/开源/商业化分组，
每条做「影响范围、可信度、与我团队相关性」评分，
只推 5-8 条重点，其余归档，高影响的追加二次检索补官方来源。
```
日报模块可分：**今日三件大事 / 模型与产品 / 开源项目 / 论文研究 / 机会与风险**，不同模块推给不同人群。

### 🚧 边界
**热度只能帮排序，不能替代事实核验。** 重要信息推送前过一遍事实核查 Skill，标注可信度。

### 📝 课后作业
搭一个你最需要的每日资讯通知（GitHub 热点、AI 日报或竞品公众号监控），跑三天，然后砍掉噪音、留下真正有用的源。

## 第 18 课 · 自动化工作流的可靠性：日志 / 异常 / 人工关口

### 🎯 本课目标
从"能自动跑"升级到"跑得稳、出错能追溯"。这是把自动化从"玩具"变成"能托付的生产力"的关键一课。

### 📖 知识点：自动化不是设完就不管
一个可靠的自动化工作流，必须回答三个问题：
1. **怎么知道它跑了、跑对没？** → 要有**执行日志**（每次跑了什么、产出什么、耗时多少）。
2. **跑错了怎么办？** → 要有**异常处理**（失败了通知你，而不是默默出错）。
3. **哪一步必须人来拍板？** → 要有**人工关口**（关键动作默认停下等确认）。

**三条可靠性原则：**

| 原则 | 做法 |
|------|------|
| 有日志可追溯 | 让任务每次执行都写一条日志（时间、动作、结果、异常） |
| 有异常会告警 | 失败/结果异常时，主动发消息通知你，别默默失败 |
| 有人工关口 | 外发、删改、写入外部系统等高风险动作，默认停下等你确认 |

### ✋ 实操案例：给自动任务加"保险"
```
优化我的每日晨报自动任务，增加可靠性：
1. 每次执行后写一条日志到「晨报日志」文档：时间、抓到几封邮件、是否成功
2. 如果某天邮箱连接失败或抓不到邮件，立刻发微信告诉我「今天晨报失败，原因 X」
3. 汇总里如果出现「疑似重要但拿不准」的邮件，单独标出来让我人工看
```

### 🚧 什么该自动、什么不该
- ✅ **适合全自动**：低风险、可验收、重复的（抓热点、整理归档、生成草稿）。
- ⚠️ **必须留人工关口**：外发邮件/消息、删改文件、写入 CRM/财务系统、对外发布内容。
> 蓝皮书的建议很清楚：**发布类动作（如自动发抖音/公众号）默认不要全自动**，除非账号、素材、标题、合规边界都经过人工确认。

### 💡 判断口诀
> 出错了只是"白跑一趟"→ 可以自动；出错了会"造成后果"（发错、删错、承诺错）→ 必须人工关口。

### 📝 课后作业
给你第 16 课设的自动任务加上"日志 + 失败告警"两道保险，故意断一次网，看它会不会通知你失败。

# 模块五 · 多 Agent 专家团

## 第 19 课 · 专家与专家团：从一个人到一支团队

### 🎯 本课目标
理解"专家"和"专家团"是什么，学会召唤和创建专家——从"AI 同事"升级到"AI 部门"。

### 📖 知识点：四种用法档位（回顾 + 深入）
| 方式 | 本质 | 适合的问题 |
|------|------|------|
| 普通任务 | 通用理解与执行 | 一次性的清楚任务 |
| Skill | 特定工具能力 | 需要稳定执行某个动作 |
| **专家** | **人设 + 方法论 + 工具链** | 明确领域的单点专业问题 |
| **专家团** | **多位专家 + 协作流程** | 需拆解、并行、汇总的复杂项目 |

**专家 = 角色切换机制。** 通过人设、方法论、工具链，让 WorkBuddy 以某领域专家的身份工作。同样分析销售数据：
- 普通 Agent：读数据 → 出图 → 总结。
- 数据分析**专家**：理解业务目标 → 定核心指标 → 查数据质量 → 找异常 → 分析原因 → 给可执行建议。

**专家团 = 协作执行机制。** 一个专家团由多位专家组成，**团长自动拆解任务、分配工作、并行执行、整合交付**。你只需告诉团长背景、需求、预期成果——不用自己挑团员、不用自己拆任务。

### ✋ 实操

**召唤一位专家：**
打开「专家·技能·连接器」→ 选「专家」→ 点「召唤专家」。以"高考我帮你"专家为例，输入任务："帮我查一下 2026 年高考数学真题"，等结果。

**创建一位专家（把你的方法论人格化）：**
点「我的专家」→「创建专家」。比如创建一个"公众号创作专家"，写清它的人设、方法论、常用工具，生成后测试，之后可在"我的专家"里随时召唤。

**召唤一个专家团：**
打开「专家·技能·连接器」→ 选「专家团」→ 点「召唤」。任务开始前先确认四件事：
1. 成员分工是否覆盖完整？　2. 哪些步骤依赖前一步？
3. 什么时候需要人来拍板？　4. 最终由谁整合？

### 💡 怎么选
- 单点专业问题 → 一位**专家**就够。
- 跨多专业、多步骤、能并行的大项目 → 上**专家团**。
- 别为了"看起来高级"给简单任务上专家团——那是杀鸡用牛刀，还费积分。

### 📝 课后作业
创建一位和你工作最相关的专家（把你的一套方法论写进它的人设），召唤它做一个真实任务，对比它和"普通任务"的产出差别。

## 第 20 课 · 多 Agent 系统设计：角色契约 + 共享产物层

### 🎯 本课目标
学会**设计**一条不断档的 AI 生产流水线——这是 L4 的核心技能。不是角色越多越好，而是每个角色都有清晰的输入、输出和边界。

### 📖 知识点一：这个任务值得拆成多 Agent 吗？
满足越多，越适合上专家团：
- 至少两个子任务可以**独立进行**；
- 子任务需要**不同的方法、资料或工具**；
- 输出可以定义清楚的**交接格式**；
- 并行能**显著缩短等待**；
- 有明确的**总负责人和最终验收**；
- 预算允许多轮调用。

> ❌ 反例：只改一封邮件、总结一份 PDF、格式化一个表格——**不需要专家团**，一个普通任务或一位专家就够。

### 📖 知识点二：角色契约（多 Agent 不乱的关键）
每个角色必须写清三件事：**输入、输出、禁止动作**。以"产品宣传片专家团"为例：

| 角色 | 输入 | 输出 | 禁止动作 |
|------|------|------|------|
| 主理人 | 用户任务描述、素材空间 | 任务拆解、状态追踪、成片 | 不跳过子任务验收直接交付 |
| Brief 角色 | 产品官网、介绍文档 | brief.md（定位、价值、目标用户） | 不直接写脚本 |
| 分镜师 | brief.md | 分镜表（时间码、画面、字幕、转场、动效） | 不引入 Brief 未确认的信息 |
| 素材师 | 分镜表 | 产品截图、概念图、界面素材 | 不使用无版权来源素材 |
| 剪辑师 | 素材、分镜表 | 逐帧 MP4 片段 | 不改动分镜结构 |
| 配乐师 | 分镜表、情绪标注 | BGM 候选及推荐理由 | 不只输出一个选项 |

**为什么"禁止动作"这么重要？** 它防止角色越界——分镜师不能自己编 Brief 里没有的卖点，剪辑师不能改分镜结构。**边界清晰，流水线才不会各说各话。**

### 📖 知识点三：共享产物层（单一事实来源）
多个 Agent **不应各自维护一份"产品事实"**，否则会出现"Brief 说 A、分镜师记成 B"的错乱。建立**单一产物路径**，大家读写同一批文件：
```
project/
├── brief.md          # 产品简报（Brief 角色产出，主理人确认）
├── storyboard.md     # 分镜表（分镜师产出，主理人确认）
├── assets/           # 素材（素材师产出）
│   └── screenshots/
├── clips/            # 逐帧片段（剪辑师产出）
└── final.mp4         # 成片（主理人整合）
```
这就是第 3 课"工作区"概念的真正用武之地——**工作区 = 专家团的共享桌面。**

### 📖 知识点四：检查点（人在关键节点拍板）
全自动 ≠ 全程不管。在关键节点设**人工检查点**：
- Brief 出来后 → 你确认"卖点抓对了吗"
- 分镜出来后 → 你确认"节奏、镜头顺序 OK 吗"
- 成片出来前 → 你确认"字幕、BGM、版权没问题吗"

> 主理人的一条铁律：**不跳过子任务验收直接交付。**

### ✋ 实操：设计你自己的专家团（练习）
挑一个你的复杂项目（如"月度经营分析"），照着填这张设计表：
1. **值不值得拆**：对照知识点一的 6 条打勾。
2. **拆几个角色**：每个角色写清 输入 / 输出 / 禁止动作。
3. **共享产物层**：定义大家读写的文件目录结构。
4. **检查点**：标出哪几步需要你拍板。

### 📝 课后作业
用上面的设计表，为你工作中的一个复杂项目设计一个专家团（先在纸上/文档里设计，不用真跑）。重点练"角色契约"和"共享产物层"。

## 第 21 课 · 实战：一句话召唤 AI 视频团队（生成 + 拆解）

### 🎯 本课目标
把前面的理论落地——用两支专家团做短视频：一支**生成**视频，一支**拆解**爆款。体验"从主题到成片全自动"。

### 📖 知识点：两支互补的团队
| 团队 | 负责什么 | 适合 |
|------|------|------|
| **视频生成团队** | 从主题出发：热点采集→选题→脚本→分镜→配音→渲染→字幕→发布 | AI 周报、产品更新、知识科普、行业分析 |
| **爆款拆解团队** | 从视频链接出发：下载→提音频→转文案→分析镜头语言→拆解报告+仿拍建议 | 学爆款结构、复盘竞品、沉淀拍摄手册 |

它们不是替代关系：**生成团队解决"今天怎么做一条出来"，拆解团队解决"为什么别人那条能火"。** 一个负责生产，一个负责学习，组合起来才能持续迭代。

### ✋ 实操 A：召唤视频生成团队
```
召唤视频生成团队，制作一条 46 秒 AI 周报短视频。
```
生成团队的四个核心角色（一条有上下游交接的生产线）：

| 角色 | 定位 | 交付物 |
|------|------|------|
| 凌导 | 主理人/团长 | 拆任务、编排并行/串行、汇总产物、处理检查点 |
| 灵阅 | 信息采集员 | 热点池、来源表、去重后的结构化摘要、选题候选 |
| 灵枢 | 内容策划师 | 选题判断、脚本、分镜、旁白、转场、素材清单、BGM/字幕节奏 |
| 灵映 | 视频制作师 | HTML 视频工程、配音、字幕对齐、转场动画、渲染成片 |

**生产流程四步（每步都有检查点）：**
1. **采集**：灵阅抓 RSS/新闻/社媒/AI 热点，去重输出结构化摘要（含标题、来源、时间、原始链接、为什么值得关注）。热度只帮排序，不替代事实核验。
2. **策划**：灵枢把主题变成镜头（选题评估、脚本、分镜、旁白、节奏、BGM、字幕停顿）。
   → 🚩 **第一次人工检查**：开头 3 秒有钩子吗？46 秒信息塞太多没？旁白准不准？画面撑得住观点吗？不过关就别进配音渲染。
3. **制作**：灵映把脚本转 HTML，调用渲染引擎（HyperFrames）出 MP4，自动完成 TTS 配音、字幕对齐、转场、素材拼接。
   → 🚩 **成片验收**：旁白与字幕一致？镜头时长匹配？文字没遮主体？BGM 可用？素材有版权风险没？
4. **发布**：可自动生成标题/标签/封面并发到抖音/视频号/B站。
   → 🚩 **铁律**：**发布默认不要全自动**，账号、素材、标题、合规都人工确认后再发。

### ✋ 实操 B：召唤爆款拆解团队
```
拆解这条视频：[视频链接]。下载视频、转写文案、分析镜头语言，
给我一份拆解报告 + 仿拍建议。
```
拆解团队角色：**阿爆**（团长/总控）、**小凯**（音频转录：ffmpeg + ASR 把口播转文案）、**小淼**（视频理解：分析景别、运镜、转场、剪辑节奏、色调、镜头时长）。
> 视频下载用**三层降级策略**（官方 API → Playwright → yt-dlp），有一层成功就继续。

### 🚧 边界（内容创作者必读）
- 拆解的目的是**学结构和方法，不是搬运原视频**。
- 视频下载/分析要**遵守平台条款、版权授权、合理使用**。
- 发布前过一遍**事实、版权、品牌**三道审核。

### 💡 闭环打法
用拆解团队分析 5 条同赛道爆款 → 沉淀成"选题评分表 + 分镜模板" → 喂给生成团队 → 生成团队按学到的规律产出 → 数据复盘 → 再优化模板。这就是蓝皮书说的"增长闭环"。

### 📝 课后作业
先用拆解团队拆一条你赛道的爆款，产出一份拆解报告；再用生成团队按学到的规律做一条 30-46 秒短视频。全程注意在每个 🚩 检查点亲自拍板。

# 模块六 · 提示词工程 · 岗位行业落地 · 毕业项目

## 第 22 课 · 提示词工程深挖：把话说到 AI 心里去

> 😰 **同样一个 AI，为什么别人用出成品，你用出一堆"再改改"？** 差别不在工具，在"你会不会说需求"。这一课把"提需求"这件事拆成公式——学会了，你下的每一句指令，它都能一次做对。

### 🎯 本课目标
系统掌握"怎么跟 WorkBuddy 提需求"——同样一个任务，会提需求的人拿到的是成品，不会提的人拿到的是"再改改"。

### 📖 知识点一：万能任务公式
> **背景 + 目标 + 输入 + 输出要求 + 边界/禁止 + 验收标准**

| 要素 | 作用 | 例子 |
|------|------|------|
| 背景 | 让它理解场景 | "我是做跨境电商的，这是给欧洲客户的邮件" |
| 目标 | 一句话说清要什么 | "把这封中文邮件改成正式英文" |
| 输入 | 给它原料 | "原文在这个文档 / 我贴在下面" |
| 输出要求 | 格式、长度、风格 | "300 字内，商务正式，带主题行" |
| 边界/禁止 | 划红线 | "不要编造未确认的发货日期" |
| 验收标准 | 什么算做对 | "对方能直接回复下单即合格" |

### 📖 知识点二：从"模糊"到"精准"的进化
| ❌ 模糊 | ✅ 精准 |
|------|------|
| "帮我写个方案" | "写一份新品上市方案，面向 25-35 岁女性，含定价/渠道/首月节奏，输出到腾讯文档，1500 字内" |
| "分析下数据" | "分析这份销售表：找出环比下滑最大的 3 个品类，给出可能原因和 2 条建议，做成表格" |
| "做个视频" | "做一条 30 秒产品介绍短视频，开头 3 秒要有钩子，突出'防水'卖点，竖屏，配字幕" |

### 📖 知识点三：五个高阶技巧
1. **给例子（few-shot）**："照这个风格写：[贴一段范例]"——比形容词管用一百倍。
2. **让它先规划（用 Plan 模式）**：复杂任务先让它出方案，你确认再执行，省得跑偏。
3. **分步下达**：大任务拆成"先做 A，我看完再做 B"，比一口气全丢过去更可控。
4. **明确"不要什么"**：负向约束（不要编数据、不要用某风格、不要超过 X 字）往往比正向更有效。
5. **让它自检**："完成后检查：字数够吗？有没有编造的事实？格式对吗？"——把验收标准也交给它。

### 📖 知识点四：提需求的三个反模式
- **一次性塞太多**：一句话里塞十个要求，它会漏。→ 拆开。
- **只给形容词不给标准**："写得高级点"——它不知道你的"高级"。→ 给例子或量化。
- **不给背景**：它不知道你是谁、给谁看，只能猜。→ 补背景。

### 📝 课后作业
挑你上周提过的一个"结果不满意"的需求，用万能公式重写一遍，对比两次产出的差别。

## 第 23 课 · 岗位落地：把 AI 装进你的具体工作

### 🎯 本课目标
不再泛泛而谈，而是落到**你的岗位**——学会用"成熟度四级"给自己规划落地路线，用"岗位场景表"找到第一个下手点。

### 📖 知识点一：岗位能力成熟度四级
别想着一步到位，按台阶走：

| 级别 | 能力 | 典型产物 | 进阶信号 |
|------|------|------|------|
| **L1 单次辅助** | 一次性帮忙 | 会议纪要、文章摘要、翻译 | 同类任务连续成功 3 次 |
| **L2 固定模板** | 可复用的稳定模板 | 周报、复盘、标准邮件 | 输入字段、验收规则稳定下来 |
| **L3 工作流** | Skill + 资料库 + 连接器串起来 | 端到端流程（如自动日报系统） | 有负责人、有日志、能处理异常 |
| **L4 团队能力** | 专家团 + 自动化 | 跨职能项目（如视频生产线） | 有权限、成本、资产治理 |

> 🎯 **给自己定位**：你现在在哪一级？下一步该积累什么才能进阶？

### 📖 知识点二：六大岗位场景速查表
找到你的岗位，从"风险低、频率高"的场景先下手：

| 岗位 | 高频场景 | 输入 | 交付物 | 风险点（人工关口） |
|------|------|------|------|------|
| 产品经理 | 需求整理、竞品分析、PRD 初稿 | 用户反馈、竞品资料 | 需求列表、竞品表、PRD 草稿 | 需求优先级需人拍板 |
| 运营/市场 | 内容排期、文案、数据周报 | 选题、后台数据 | 排期表、文案、周报 | 对外发布前审核 |
| 销售/售前 | 客户资料整理、方案、跟进纪要 | 客户信息、产品资料 | 客户画像、方案初稿 | 报价/承诺需人确认 |
| HR/行政 | JD 撰写、简历初筛、制度整理 | 岗位需求、简历 | JD、初筛结果、制度文档 | 录用决策不能全交 AI |
| 财务/法务 | 数据整理、合同要点、报表初稿 | 流水、合同 | 汇总表、要点清单 | 合规/金额必须人工复核 |
| 研发/IT | 文档、代码解释、日志分析 | 代码、日志、需求 | 文档、排查建议 | 上线/删改需人工执行 |

### 📖 知识点三：部门推广模板卡
想在团队推广？照这张卡把一个流程说清楚，谁接手都能复用：

| 字段 | 内容 |
|------|------|
| 原流程 | 原来这件事怎么做、几个人、多久 |
| 输入 | 需要哪些资料/文件/权限 |
| 输出 | 产出什么、什么格式 |
| 验收标准 | 什么算合格 |
| 人工关口 | 哪几步必须人来拍板 |
| 关键指标 | 用什么衡量效果（省时/质量/成本） |
| 负责人 | 谁维护、谁背锅 |

### 📝 课后作业
用"成熟度四级"给自己定位，再从你岗位的场景表里挑一个"风险低、频率高"的场景，写一张部门推广模板卡。

## 第 24 课 · 毕业项目：从零搭一条属于你的 AI 生产线

### 🎯 本课目标
把整门课学的东西串起来，**独立完成一个端到端项目**。这是你的结业作品，也是你未来向团队展示的样板。

### 📖 毕业项目要求
选一个**你工作中真实、重复、有价值**的流程，用 WorkBuddy 把它做成一条能复用的生产线。必须覆盖：

- ✅ **至少 1 个连接器**（邮箱/文档/飞书/Notion 等）
- ✅ **至少 1 个 Skill**（官方或自己搭的）
- ✅ **一套稳定的提示词/模板**（用万能公式写）
- ✅ **可复现**（换个输入也能跑，不是一次性）
- ✅ **明确的人工关口**（标出哪一步你要拍板）
- ✅ **进阶项（可选）**：定时自动化 / 多 Agent 专家团 / 执行日志

### ✋ 三个参考选题（按难度）

**🥉 入门级 · 每周竞品动态简报**
连接器（公众号监控/GitHub 热点）+ 资讯 Skill + 固定周报模板 → 每周五自动生成竞品动态，发到飞书。对应 L2→L3。

**🥈 进阶级 · 客户资料到方案的流水线**
连接器（腾讯文档）+ 客户画像 Skill + Plan 模式方案模板 → 输入客户信息，产出画像 + 方案初稿，报价处留人工关口。对应 L3。

**🥇 挑战级 · 内容生产 + 拆解双团队**
视频生成团队 + 爆款拆解团队 + 共享产物层 + 发布人工关口 → 拆解 5 条爆款沉淀模板，喂给生成团队产出短视频，形成增长闭环。对应 L4。

### 📋 交付清单（做完自查）
1. 一段话说明：这条生产线解决什么问题、原来怎么做、现在怎么做。
2. 流程图或步骤说明：每一步谁（哪个 Skill/专家）做、输入输出是什么。
3. 用到的提示词/模板（可复制）。
4. 人工关口清单：哪几步你拍板、为什么。
5. 一次真实运行的结果截图/产物。
6. 复盘：省了多少时间、还有什么坑、下一步怎么优化。

### 🎓 结业寄语
> 学完这门课，你手里有的不是"会用一个 AI 工具"，而是**一套把重复工作变成可复用生产线的方法论**。工具会变，但"拆解任务 → 定义角色 → 划清边界 → 留好人工关口 → 持续复盘"这套思路不会过时。去把你工作里最烦、最重复的那件事，做成第一条生产线吧。

## 附录 B · 避坑手册（12 条真实教训）

1. **用连接器前先在设置里开授权**——没开就让它连邮箱/文档，一定失败。
2. **自动任务要电脑开机**——它在你本机跑，关机就断。
3. **发布类动作别全自动**——发抖音/公众号默认留人工确认，账号/合规/版权先过一遍。
4. **财务、法务、录用决策不能全交 AI**——涉及金额、合规、人的决定，必须人工复核。
5. **别一句话塞十个要求**——它会漏，拆开分步下达。
6. **重要数字让它标来源**——"这个结论基于哪份数据？"防止它编。
7. **明确说"不要什么"**——负向约束比正向更有效（不要编、不要超字数、不要用某风格）。
8. **复杂任务用 Plan 模式**——先出方案你确认，别让它闷头跑偏。
9. **热度 ≠ 事实**——资讯类结果推送前过一遍事实核查。
10. **专家团不是越多越好**——简单任务上专家团是浪费积分，先判断"值不值得拆"。
11. **多 Agent 要有共享产物层**——否则各记各的，Brief 和分镜对不上。
12. **积分会花**——图片/视频比文字费积分，跑大任务前看下余额，先手动小跑再放大。

## 附录 D · 术语表（小白友好）

| 术语 | 一句话解释 |
|------|------|
| Agent（智能体） | 能自己拆解并完成任务、直接出成品的 AI，不只是聊天 |
| Craft 模式 | 立即执行，90% 日常用它 |
| Plan 模式 | 先出方案给你确认，再执行，适合复杂任务 |
| Ask 模式 | 只聊天、不碰你的文件 |
| Skill（技能） | 一个能稳定执行某动作的工具能力（如抓 GitHub 热点） |
| 连接器 | 把 WorkBuddy 连到你的邮箱/文档/飞书等，让它能读写 |
| 专家 | 带人设+方法论+工具链的 AI，某领域的单点高手 |
| 专家团 | 多位专家 + 团长协作，处理需拆解的复杂项目 |
| 团长/主理人 | 专家团里负责拆任务、分配、整合交付的角色 |
| 角色契约 | 每个角色的 输入/输出/禁止动作，防止越界 |
| 共享产物层 | 多个 Agent 读写同一批文件的目录，保证"单一事实" |
| 检查点/人工关口 | 关键步骤停下来等你拍板的地方 |
| 工作区 | 一个任务相关文件的集合，也是专家团的共享桌面 |
| 成熟度 L1-L4 | 从"单次帮忙"到"团队生产线"的四级能力台阶 |

| 积分 | WorkBuddy 的用量货币，任务越重耗得越多 |

## 附录 E · 学习路线图与进阶建议

**按周学习节奏（建议）**
| 周 | 学什么 | 目标产物 |
|------|------|------|
| 第 1 周 | 模块一（1-6 课）| 装好、跑通第一个任务、熟悉三模式 |
| 第 2 周 | 模块二（7-11 课）| 用它完成一次真实办公任务（文档/PPT/表格/数据） |
| 第 3 周 | 模块三（12-15 课）| 接一个连接器 + 装一个 Skill，跑通一条小流程 |
| 第 4 周 | 模块四（16-18 课）| 搭一个每日自动任务 + 加日志告警 |
| 第 5 周 | 模块五（19-21 课）| 召唤一次专家团，跑一条视频生产/拆解 |
| 第 6 周 | 模块六（22-24 课）| 完成毕业项目 |

**三条进阶心法**
1. **先解决自己最烦的事**——从你每天/每周重复做的一件事下手，最有动力也最见效。
2. **每个能跑通的流程都存成模板**——积累模板库，就是积累你的"AI 生产力资产"。
3. **边界感比效率更重要**——知道"哪些能全交 AI、哪些必须自己拍板"，才能长期放心地用。
